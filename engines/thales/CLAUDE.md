# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working on the thales engine.

## What this engine is

Thales is lakatos's proof engine. It backs `lakatos prove`: annotated TypeScript is emitted as plain Lean 4, Lean attempts to prove each `@ensures` property against a model of each function, and one SZS verdict per annotation comes back to the CLI as a JSON line.

This is a ground-up rewrite; the previous whole-file subset-checking compiler (its `Thales/` library, `thales` executable, TH-code diagnostics, and conformance harness) has been removed, and the layers of the new engine are landing slice by slice. If a doc or comment mentions those, it predates the rewrite.

The engine has two halves in two languages:

- **`frontend/` (TypeScript)** — the emitter. Part of the root npm package: compiled by the root `tsconfig.json` and tested by the root vitest suite. `emission.ts` walks tsc's AST into per-declaration JSON and classifies what it cannot map, `emission-artifacts.ts` writes those JSON files under the run directory the CLI hands it, `readings.ts` holds the source readings the emitter and its tests share, `module-graph.ts` resolves the import closure, `run.ts` shells out to lake/lean and parses verdict lines.
- **`ThalesDsl/` + `Js/` (Lean 4)** — the prover and the JS-semantics library it draws on, two lake libraries plus the `thales-emit` executable; artifacts are run with `lake env lean`. Pinned toolchain: `leanprover/lean4:v4.33.0` (`lean-toolchain`). The boundary rule: nothing under `Js/` may mention `ThalesDsl` or any emission concern — lakatos owns syntax and search, the library owns meaning.

Annotation parsing is NOT here: file discovery, `@ensures` extraction, and prefix/formula parsing all live in `lemma/` at the repo root. The frontend consumes lemma's parsed output; the Lean side never sees Lemma syntax.

## Common commands

From `engines/thales/`:

```bash
lake build                       # build the ThalesDsl library
lake build ThalesDslTest         # Lean tests under Test/
lake env lean Test/ThalesDsl/NormTest.lean    # one Lean test file in isolation
lake build thales-emit           # the emission executable (not a default target)
npm run check:verdict-channel    # verdict-line contract over tests/fixtures/*.lean
npm run check:envelopes          # emission envelopes against stored expectations
                                 # (LAKATOS_PROVE_E2E=1 adds the corpus manifest)
UPDATE_ENVELOPES=1 LAKATOS_PROVE_E2E=1 npm run check:envelopes   # regenerate the store
```

From the repo root (the frontend is root-package code):

```bash
npx tsc -p tsconfig.json                      # build (the check scripts need this first)
npx vitest run engines/thales/frontend/tests  # frontend unit tests
npm run format:check                          # prettier, whole repo, one config
LAKATOS_PROVE_E2E=1 npx vitest run tests/e2e.test.ts   # full prove e2e (needs Lean)
```

Always wrap `lake env lean` invocations in a timeout when running them by hand; a bad artifact can grind indefinitely.

## The prove pipeline

`lakatos prove` (in root `src/cli.ts`) runs one spine. Its stages:

1. **Discover + extract** — `lemma/`'s `resolveFiles` and `extractFromSource` find `@ensures` annotations; malformed ones become `InputError` envelope entries.
2. **Emit** (`frontend/src/emission.ts`, `frontend/src/emission-artifacts.ts`) — described below: per-declaration JSON per annotated file, written into the run directory's `thales/` mirror (gitignored in the target project; a file whose annotations are all classified gets no artifact).
3. **Render + run** (`frontend/src/run.ts`) — `findEngineRoot()` walks up from this module looking for the lakefile (absent → `no-project`); then `lake build` once, `lake build thales-emit`, the emitter per artifact, and `lake env lean <artifact>` per file (timeouts: `BUILD_TIMEOUT_MS` 600s, `LEAN_TIMEOUT_MS` 300s; injectable `spawn` for tests). A failing artifact is contained as a per-file `FileFailure` — the run still completes and healthy verdicts still ship.
4. **Join** — root `src/envelope.ts` matches verdict lines to annotation identities; missing, duplicate, surplus, or unrepresentable statuses make the run unhealthy (NotTried envelope, stderr diagnostics, exit 2).

### What the emitter does

`frontend/src/emission.ts` walks the tsc AST into per-declaration JSON (`schemas/thales-emission.schema.json`), settling frontend-side everything an annotation's fate can be settled by before Lean sees it: an unmappable construct or a refused operator (`**`) classifies `Inappropriate` — as does an `Object.is` argument that is statically not a number, since SameValue is modeled over numbers only — a safe-integer-clamped range classifies `NotTried` with kind `unsupported-range` when the clamp is the sole structuring blocker (and unconditionally when the clamp empties the interval), while the engine's own gaps — an operator with no model, a type mismatch, an unbound identifier, a callee that is unregistered, later-declared, wrong-arity, or engine-failed — classify `Error`. Every name a non-function declaration binds (variable declarators, destructuring included; enum/interface/type/namespace names) registers as a failed declaration, so a call to one degrades its caller. Relative imports are followed: the entry file's dependency closure is walked ahead of it, each dependency's declarations emitted into the entry's own artifact before their users under models qualified by the dependency's path relative to the entry, with imported spellings resolved to them — artifacts stay self-contained, at the cost of duplicating a shared dependency across the artifacts that import it. Registries are keyed by module and name together, since a module path and a class qualification cannot share a flat key. Only the entry's annotations become obligations; a dependency's belong to its own artifact. What stays opaque, registering as a failed declaration like any other unmapped binding: a bare specifier, a relative one that reaches no file, a name the target module does not declare, a default or namespace import (a module object has no shape in the model), and the edge that closes an import cycle — which degrades the cycle's names, never the entry's own. The walk is disciplined: typed positions (`num`/`bool`), scope, source-order model registration, and a fixed pre-scan order (opaque constructs, then refused operators, then construct-failed callees, then the typed walk — each scan across the whole body before the next begins, dead code included), so which failure gets reported never depends on walk order. The lowering ends at the first return (what follows never reaches the artifact), a body that can run off the end degrades, and a failed overload signature never blocks a name the implementation models. Classified annotations never reach Lean. The `thales-emit` lake executable (`ThalesEmit/`) decodes that JSON strictly and renders a readable artifact — ordinary `def`s under the `TsModel` namespace with call sites qualified (so no root-level name collides and no binder captures a callee; a binder or parameter spelled like the artifact's own unqualified vocabulary — `pure`, `ballIco`, `Float`, … — is primed), over `JsNumber`/`JsM` and tagged `@[js_norm, grind]` so the symbolic rungs can unfold them, do-notation bodies with calls lifted via inline `←` in JS evaluation order, statement bodies as one do-statement per source statement — `const` as `let`, a mutable local as `let mut` with `:=` reassignment, `if`/`else if`/`else` (arms that return, throw, or fall through all compose, Lean's do-elaborator doing the control-flow lowering, so no tail is duplicated and no helper lambda reaches the text), `throw` as `throw (JsError.error "Kind")`, an assigned parameter rebound `let mut x := x` ahead of the body, locals ascribed `: JsNumber` so literal initializers don't elaborate at `Nat` — the full operator slice (`%` as `Number.FloatOps.tsRem`, comparisons as the IEEE `Float` predicates with `>`/`>=` flipped, `===`/`!==` as `Float.beq`, `Object.is` as `Number.FloatOps.sameValue` — the SameValue atom the walk admits wherever a boolean is expected, branch conditions and guards alike — the logical operators `||`/`&&`/`!` over operands that are themselves modeled booleans, which today means branch conditions (Lemma's leaf rule spells a formula's own connectives `∧ ∨ ¬`, so an atom never carries them at its root) and the `!` a `≢` guard desugars to: a pure right operand lowers to the `Bool` operator, a lifted one renders behind the choice — ascribed `JsM Bool`, since an unascribed nested `do` reads its return type off the enclosing one — so JS's short-circuit effect order is preserved and a throw in the right arm never fires when the left settles the answer, while any non-boolean operand refuses the operator, truthiness having no model — the builtin member-call whitelist as core `Float` primitives — `Math.sqrt` as `Float.sqrt`, exactly specified and correctly rounded, `Math.abs` as `Float.abs`, and the boolean-valued `Number.isFinite`/`Number.isNaN` as `Float.isFinite`/`Float.isNaN`, admitted wherever a boolean is expected, guards and branch conditions alike — so the namespaces' unlisted names (`Math.pow` among them) keep their unmapped-construct refusal; a binding of the namespace spelling itself — parameter, local, module-level declaration, or import, degraded ones included — wins over the whitelist exactly as one wins over the `NaN`/`Infinity` atoms, since a shadowed `Number.isFinite` typechecks while meaning something else entirely; its finite arm reaches `Nat.sqrt`, which the kernel unfolds and elaboration declines to, so the decide rung proves a bounded sqrt claim while the witness search cannot read a refutation back — and the `NaN`/`Infinity` globals as expression atoms, in bodies and formula atoms alike, spelled `floatNaN`/`floatInf` and both kernel-reducible; they are a fallback, never keywords, so any binding of those spellings — parameter, local, module-level declaration, or import, degraded ones included — shadows them, and `-Infinity` is unary minus over the atom), `≡` conclusions as `JsM` equality, boolean islands as `= pure true`, bounded binders as `ballIco`, unbounded int/nat as plain `∀`s and `number` binders as a `JsNumber` ∀ carrying whichever bounds it has as hypotheses (lower outermost, an infinite endpoint as `floatInf`), a class-valued binder as one ungrouped `∀` per constructor argument — spelled `«p.x»`, which no Lemma identifier can collide with — then the instance and the hypothesis naming it as `construct`'s output, so the guards and the `-0` normalization are part of the domain by construction rather than by restatement; the class and every one of its constructor parameters must be inside the model, and a binder whose class is degraded travels that class's own reason, a guard chain as `= pure true` hypotheses in front of the conclusion, an `≡` guard among them (a `≢` guard walks as `!` over the SameValue atom) — recovered on the Lean side by `ProveTerm.propSpine` and threaded into the witness search, so a reported witness satisfies every guard — echo comments above each block — building every line of code via quotations and Lean's pretty-printer, never string concatenation. A dependency's models sit one component deeper — `TsModel.«helper.mts».double`, the module's entry-relative path as one guillemet name component, which parses, resolves, and pretty-prints back unchanged, while the entry's own stay bare so no existing artifact changes; a path that would break its own component is refused with a message naming the gap. A number-typed class models as a `TsModel` structure over its fields — each field keeping its source spelling as one name component, a `#`-private guillemeted — with the constructor as `C.construct : ... -> JsM C` under a checked precondition that every field is assigned exactly once on every path (a violation degrades the whole class with a reason naming the precondition, as does a bad field, a parameter property, or a missing or duplicated constructor implementation), each getter as an instance-taking def whose receiver is `self` (which joins the reserved vocabulary, so a source `self` is primed), each instance method as that same instance-taking shape over its parameters — dual-tagged and its assigned parameters rebound `let mut` exactly as a free function's are, and rendered after the getters — with a member body's `this.m(args)` and an atom's `new C(a).m(b)` alike lowering to that def applied receiver-first, so a receiver whose constructor throws propagates ahead of the arguments in JS evaluation order; a member body resolves methods in source order, calling only what has already modeled, so a forward, self-recursive, or getter-to-method call degrades the caller alone, and the builtin whitelist never collides with a class's own methods, since a `new C(x).m(y)` receiver is not an identifier and a bound `Math`/`Number` spelling already declines the builtin; and per-member containment everywhere else: a static member, a private member, an unmodelable method, or a getter or method that writes a field degrades alone while its siblings still model, and the never-attempted list — `extends`/`super`, setters, static blocks, index signatures, computed member names, decorators, abstract and declare classes — degrades the class before any member is walked. Formula atoms and bodies alike gain `new C(args)`, member access on the result — dispatching to a getter or a field — and method calls on it, with the same classification travel a call has: an atom naming a degraded class or member carries that degrade's own reason, while arity, unknown-member, unknown-method, and instance-as-a-number misuse stay the engine's `Error`. Every parameter — a free function's, a constructor's, a method's — is typed `number` or at a class that has already modeled (the enclosing class itself included, which a constructor's own parameter cannot name), so a type reaching a later-declared class keeps its unmapped-construct refusal and one naming a degraded declaration travels that failure; a class-typed parameter then flows as an argument where the callee's signature expects that class and as a receiver for its own field, getter, and method reads, with every argument typed at the callee's declared parameter type rather than at `number`. Locals, fields, and return types stay number-only: an instance-valued local keeps its refusal. Each parameter's type rides the emission wire (`{name, type}`, the type `"number"` or `{class, module?}`) and renders as its own binder group, runs of one type sharing a group. `frontend/src/emission-artifacts.ts` writes one emission JSON per annotated file into the run directory (a fully classified file gets no `.lean` at all), `runEmission` in `frontend/src/run.ts` builds `thales-emit` and renders each artifact before the lean pass, and a failed emit is contained per file — that file's annotations report `Error`, siblings still verdict, exit 2. `scripts/check-envelopes.js` runs the pipeline over a fixture manifest and requires the projected envelope entries equal to the ones stored in `tests/fixtures/envelopes.expected.json` (regenerate with `UPDATE_ENVELOPES=1`, which insists on the full manifest so the store never goes partial); without `LAKATOS_PROVE_E2E=1` only the tracer and class-binder fixtures run, with it the operators, statements, binders, and degradations fixtures and the conformance corpus's expression, statement, binder/guard, unsupported-range, and import slices too — the Error family included. Timeout fixtures are graded under the same reduced heartbeat budget the corpus harness uses, where Timeout is deterministic and cheap. The golden artifacts are pinned as `tests/fixtures/*.emitted.lean.expected`. Emitted artifacts pin `set_option autoImplicit false`: they run under lean's defaults, not the lakefile's options.

## The verdict channel

Each `#thales_prove` prints exactly one line to stdout: `thales-verdict:` + compact JSON `{identity, szs, reason}`. Stdout is also Lean's diagnostic stream; only sentinel-framed lines are contract, everything else is forwarded as diagnostics.

Verdict meanings, as the ladder assigns them:

- `Theorem` — a rung of the ladder succeeded; the proof was added to the environment. The reason says which trusted base it rests on, read off the theorem's own axioms: kernel-checked, or admitted from a compiled evaluation that trusts the compiler and the host's floating point unit. The verdict's `axioms` field names those non-standard axioms verbatim — empty for a kernel-checked proof — and travels into the envelope entry.
- `CounterSatisfiable` — a decide tier established the property is false on its bounded domain, and the domain was searched for a concrete witness, shipped in the verdict's `counterexample` field (binder name → value; values outside the JS safe-integer range travel as decimal strings). The search reduces in the elaborator, which cannot evaluate a `Float` coerced from a large integer, so falsity established at that end of the range ships without a witness as the false-on-domain `GaveUp` instead.
- `GaveUp` — the ladder exhausted; the reason carries the pretty-printed residual goal that stumped the prover (or, in rung 1, the false-on-domain diagnosis with no witness to ship — including when the witness search itself ran out of budget, since established falsity is never given back for the cost of illustrating it). A rung that blows the recursion limit (`maxRecDepth`) has failed, but the annotation has not: the ladder falls through to the next rung and the goal reported is whatever survived.
- `Inappropriate` — the annotation is outside the model, not beyond the engine: the function could not be modeled because of an unmapped TypeScript construct (opaque node) or an operator the model refuses on the merits (`**`), or the property mentions such a declaration or operator itself. The reason names the construct or operator; `Error` stays reserved for the engine breaking.
- `Error` — the attempt failed for any other reason; the reason names the phase that failed — building the property, or searching for a proof — so neither is ever blamed for the other's failure.
- `NotTried` — no structured property was provided (the emitter's bare-payload degradation path).
- `Timeout` — the attempt exceeded the per-annotation heartbeat budget (`thales.heartbeats`, overridable per run via `LAKATOS_PROVE_HEARTBEATS` → `-Dweak.thales.heartbeats=N`); later annotations in the file still run, each with a fresh budget. A budget of 0 is not a budget: `maxHeartbeats 0` means unlimited, so the option floors at 1 and the frontend ignores `LAKATOS_PROVE_HEARTBEATS=0` rather than forwarding it.

The set lives in exactly two places, one per language: the `Szs` inductive in `Verdict.lean` and the `SZS_STATUSES` array in root `src/szs.ts`, whose `ProveStatus` is that array minus the CLI-only statuses — `InputError` (extraction happens before the prover) and `User` (an interrupted prover reports nothing at all; the CLI synthesizes those entries from the signal that killed the run). The root suite pins the two against each other (`tests/verdict-contract.test.ts`), constructor names and wire spellings alike. Everything else — the envelope's check, the frontend's parser, the check scripts — derives from the TypeScript side, so a new status means one edit per language and nothing else.

A verdict must also explain itself: an empty `reason` is a contract violation, contained like any other malformed line.

## Tests and checks

- `Test/ThalesDsl/` — Lean unit tests (`lake build ThalesDslTest`; each file also runs in isolation via `lake env lean`).
- `frontend/tests/` — vitest unit tests for emission, emission-artifacts, module-graph, and run (run from the repo root; `run.test.ts` uses the injectable spawn, no real Lean needed).
- `scripts/check-verdict-channel.js` — the verdict-line contract over the hand-written fixtures in `tests/fixtures/*.lean`.
- `scripts/check-envelopes.js` — end-to-end over the fixture manifest: emits, renders, runs, and compares the projected envelope entries against the stored expectations.
- Both read the channel through the _built_ frontend (`scripts/harness.js` loads it, so a root build is required): the sentinel, the parse, the verdict validation, and the lake invocation are production's, not a copy the scripts could drift from.
- Root `tests/e2e.test.ts` — the full CLI prove path, gated on `LAKATOS_PROVE_E2E=1` so local and CI coverage stay identical.

CI: `.github/workflows/thales.yml` runs lake build, the Lean tests, both check scripts (the envelope one over the full manifest), and the gated prove e2e. The root `lakatos.yml` covers the frontend's vitest suite as part of the root package.

`tests/conformance/` is the verdict-fixture corpus: `.ts` fixtures bucketed by the SZS status every annotation in them must receive, run end to end by the root `tests/verdict-corpus.test.ts` (gated like the prove e2e). Its README documents the bucket conventions.

## Conventions

- **`autoImplicit` is off** project-wide (`lakefile.lean`); bind all implicit/universe variables explicitly.
- **Failure containment over abortion.** A construct the engine can't handle degrades that declaration (a failed declaration), that annotation (`NotTried`/`Inappropriate`), or that artifact (`FileFailure`) — never the whole run. New frontend features should preserve this.
- **One verdict line per `#thales_prove`, always** — even for failures the elaborator can see. The check scripts enforce ordering and framing. Annotations the frontend classifies itself (unsupported ranges, refusals) never enter the verdict channel; the CLI joins their verdicts in from the emission's `classified` list.
- **The Lean library builds here; the frontend builds at the root.** This directory's npm package (`thales-dev`) exists only for the check scripts; it has no dependencies. Formatting is a root-only operation: one prettier pin, one config, covering this directory too.
