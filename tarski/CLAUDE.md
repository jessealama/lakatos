# CLAUDE.md

## What this package is

Tarski is lakatos's JS-semantics library: the Lean definitions that give TypeScript's values and operations their meaning. `lakatos prove` (thales) proves `@ensures` properties against models built from these definitions. The package is shared: thales requires it by path (`require tarski from "../../tarski"` in `engines/thales/lakefile.lean`); no engine may be required by it. The boundary rule: nothing here mentions `ThalesDsl` or any emission concern — lakatos owns syntax and search, this library owns meaning.

It holds two things over one set of definitions. `Js/` is the semantics library. `Tarski/` is an evaluator for a fragment of JavaScript — a definitional interpreter whose every primitive operation _is_ one of the library's, so a `Theorem` and a run appeal to the same meaning. The evaluator's parser is not in Lean: `frontend/` is a TypeScript bridge over tsc that emits ESTree JSON, and `schemas/tarski-estree.schema.json` at the repo root is the seam. Growing the evaluator is GitHub epic #376.

The Lean toolchain pin is `lean-toolchain` here; `engines/thales/lean-toolchain` is a symlink to it. `lake-manifest.json` is tracked.

## Common commands

From `tarski/`:

```bash
lake build                          # the Js library, the evaluator, the binary
lake build tarski                   # just the evaluator's binary
lake build TarskiTest               # the Lean tests under Test/Js/ and Test/Tarski/
lake env lean Test/Js/NormTest.lean # one test file in isolation
sh scripts/check-boundary.sh        # the evaluator's arithmetic boundary
```

The binary lands at `.lake/build/bin/tarski` and takes one ESTree document:

```bash
node ../dist/tarski/frontend/src/bridge-cli.js t.js t.json   # after npm run build
.lake/build/bin/tarski run t.json
```

The bridge and its tests are part of the repo-root npm package, not this lake package: build, typecheck, test, and format them from the repo root.

Wrap `lake env lean` in a timeout when running it by hand; a bad artifact can grind indefinitely.

| `Js.lean`                                                             | The umbrella import: every module below, in dependency order. Artifacts and tests `import Js`.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `Js/Runtime.lean`, `Js/Number/Basic.lean`                             | The domain: `JsM α := Except JsError α`, `JsNumber := Float`, `floatNaN`. **Computability is the invariant** — `decide` must evaluate models over bounded domains.                                                                                                                                                                                                                                                                                                                                                           |
| `Js/Val.lean`                                                         | The tagged `JsVal` domain for unions, optionals, and booleans: `toNumber`/`toBoolean` (throwing projections), `typeof`, `strictEq`, `sameValue`.                                                                                                                                                                                                                                                                                                                                                                             |
| `Js/Binders.lean`                                                     | Binder-domain meaning: `floatInf` and `ballIco` (bounded ∀ over `[lo, hi)`) with its `Decidable` instance. The witness scans live in the prover, not here.                                                                                                                                                                                                                                                                                                                                                                   |
| `Js/Norm.lean` (+ `Js/NormAttr.lean`)                                 | The `js_norm` simp set: what lets pure-looking code shed its monadic wrapping so the closers see bare arithmetic; dual-tagged for grind. A lowered branch is split into one obligation per arm carrying its condition — the only shape in which a literal arm becomes a ground term. Vanilla Lean has no binary64 theory, so each recurring residual goal is one lemma to add here. `NormAttr` registers the attribute one module below the lemmas, since a simp set is only usable in modules that import its registration. |
| `Js/Number/FloatOps.lean`, `Constants.lean`                           | Binary64 operations JS has and Lean does not (`tsRem`, the roundings, `tsSign`, `tsFround`, `tsMin`/`tsMax`, the integer predicates, `sameValue`) and the `Math`/`Number` constants under their source spellings. Built from `Float.Model`, never `extern`, so the kernel can reduce them; `MAX_VALUE`/`MIN_VALUE` are spelled by bits because their decimals do not reduce.                                                                                                                                                 |
| `Js/Number/FloatFacts.lean`, `FloatOpsFacts.lean`, `FroundFacts.lean` | Kernel-checked theory about binary64 and the models above (monotonicity against a bounded constant, order transitivity and totality away from NaN, the roundings' and clamps' defining inequalities). Residual goals are over `Float`, whose every op is `pack (op (unpack ..))`, so an `UnpackedFloat` fact reaches one only through the `Canonical` round-trip. `FroundFacts` is the order theory of `Math.fround`: each stage of the narrowing is monotone on values, so the composite is.                                |

## The evaluator

| Module                      | Role                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Tarski.lean`               | The umbrella import, in dependency order, as `Js.lean` is for the library.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `Tarski/Ast.lean`           | The evaluated fragment's syntax. Each constructor's doc comment names the ESTree node it decodes from, so the AST, the decoder, and the schema are readable against one another.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `Tarski/Value.lean`         | `Value`, `Obj`, `Closure`, `Cell`, `Heap`, `Env`, `Completion` — the domain. **Bindings are heap cells, not environment entries**: that is what makes an assignment inside a loop visible after it, and what a closure captures. A cell's `value` is optional, and `none` is **the temporal dead zone**. An `Obj` is a prototype link, own data properties in insertion order, an optional `Callable`, and an `ObjKind`; descriptors and accessors are #389's. **`ObjKind` is the exotic-object classification**, and an array's `length` lives there rather than among the properties, so it is never enumerated, never shadowed, and truncation is one field write; the elements are index-keyed own properties, so a hole is a key that is not there. **`Value.ofNat` is the one widening the evaluator performs** — a length or an index becoming a Number. A `break` and a `continue` **carry the completion record's `[[Value]]`**. `ErrorKind` is the seven `Error` classes; a **built-in is a `NativeFn`**, a closed enum `callNative` interprets, not a `Closure` — a native constructor must construct when called without `new`, which no AST spells.                                                                                                                                                                                                                                                                                                                               |
| `Tarski/Monad.lean`         | `EvalM := ExceptT Completion (StateT Heap Option)`. That order, not the other one: it pairs the heap with the whole `Except`, so **an abrupt completion carries the heap out beside it** and a caught `return` keeps the writes it made. The `Option` is divergence, and **nothing writes it by hand** — it is only the fixpoint's bottom. `partial_fixpoint` has no monotonicity lemma for `tryCatch`, so **catching is an opaque definition with its own `@[partial_fixpoint_monotone]` lemma, and there are exactly two**: `catchReturn`, and **`attempt`, which reifies a completion instead of swallowing one shape of it**. Every other catch — a `try`, a `finally`, a loop's `break`, a label's — is **an ordinary `match` on what `attempt` answered**, inside the fixpoint block, so a catching arm may recurse. `throwJsError` allocates a real `Error`, `newObject` is OrdinaryObjectCreate against `Object.prototype`, and `newArray`/`newArrayOfLength` are ArrayCreate. The three `run_*` lemmas here are the plumbing core does not supply; a proof adds `ExceptT.run_bind` to its own set.                                                                                                                                                                                                                                                                                                                                                                                    |
| `Tarski/Eval.lean`          | The interpreter: one `mutual` block under `partial_fixpoint`, so its equations are theorems and no fuel parameter exists. Primitive operations delegate to `Js`. What is **inside** the block is what can reach user code — `getProp`, `toPrimitive`, and `setProp` can (ArraySetLength coerces its value, which is ToPrimitive on an object), `instantiateBlock` and `makeFunction` cannot. What **never joins a simp set** is what recurses on something other than syntax: **`evalWhile`, `getProp`, `protoChainHas`, and `joinElements`**, each unfolded one step at a time with `rw`. **ToPrimitive takes a hint**: `+`, the relations, and the unary operators pass `number`, while `String(v)`, `join`, and ToPropertyKey pass `string`, and **`toStringValue` is ToString on values**. Strings are Lean `String`s and so **code points, not UTF-16 code units**, for `length`, indexing, and the relational order; #391 owns the difference. `instantiateBlock` is BlockDeclarationInstantiation over a list's direct declarations, and is the only thing that grows an environment. **`evalStmt` threads the running completion value** and answers the updated one: that is UpdateEmpty done once rather than at every statement list, and it is what gives a `break` its value. `evalBlock`, `evalCatch`, `evalLabeled`, and `evalLoop` are the statement forms around it. **The messages the evaluator raises are one table in the module header**, and nothing invents a new one. |
| `Tarski/Decode.lean`        | `Lean.Json` → `Program`, written to the schema. The only place that says `unsupported`, and the only module importing `Lean.Data.Json`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `Tarski/Format.lean`        | Provisional `Value → String` for the binary. `formatNumber`'s doc comment is **the one place that says what the placeholder does and does not do** — exact for integers below 2^53, both zeros, and the non-finite values; no shortest round-trip, no exponent form, nothing below six fraction digits. #388 replaces one function.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `Tarski/Realm.lean`         | The intrinsics at **fixed heap references**, twenty-six objects and ten cells: the seven `Error` prototypes at 0–6, their constructors at 7–13, `Error.prototype.toString` at 14, `Object.prototype` at 15 with `hasOwnProperty` and nothing else (the rest is #389's, so `{} + 1` still throws), `Object` and its three natives at 16–19, `Array.prototype` at 20 — itself an array of length 0 — `Array` and its three natives at 21–24, `String` at 25, and the global bindings in cells 0–9. `Error.prototype` now chains to `Object.prototype`. `Heap.initial` is a **literal**, so `throwJsError` can name a prototype without searching for one and `simp` carries the realm as data; `Test/Tarski/RealmTest.lean` pins the literal against the constants. `Heap.empty`, in `Value.lean`, is the heap with no realm.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `Tarski/Main.lean`          | `tarski run <file.json>`. Exit codes are documented in its header: 0 ran, 1 uncaught, 2 bad input, 3 unsupported; an uncaught throw prints **`Uncaught <name>: <message>`** for an Error object and the value's printed form otherwise. Divergence is not one — the caller imposes a timeout.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `frontend/src/`             | The parser bridge (`estree.ts`) and its command (`bridge-cli.ts`). A construct outside the fragment becomes an `Unsupported` node in place — a parameter, an object-literal member, and a call argument each refuse alone, so the node around them survives — and **Lean owns every refusal verdict**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `scripts/check-boundary.sh` | The arithmetic boundary. Every `Float`-namespace call and method-syntax Float operation is banned under `Tarski/`, because Lean's own `Float` instances _are_ the library's model of `Number` and the sanctioned spellings are the infix ones. `Tarski/Format.lean` is exempt until #388. CI runs it against `scripts/boundary-fixture/`, which plants a violation, so the check's own bite is checked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

## Tests

`Test/Js/` and `Test/Tarski/` — Lean unit tests, one file per concern; `lake build TarskiTest` builds them all and each runs alone via `lake env lean`. Library test files import only `Js` and its submodules.

`Test/Tarski/fixtures/numeric-loop.json`, `counter.json`, `errors.json`, `uncaught.json`, `harness-floor.json`, and `compare-array.json` are the parser bridge's output byte for byte; `tarski/frontend/tests/bridge-cli.test.ts` holds the two copies of each together, and the tarski workflow runs the binary on all six. `counter.json` is #378's own example and prints `true`; `errors.json` is #379's and prints `zero!`; `harness-floor.json` is #380's and `compare-array.json` is the test262 harness's `compareArray`, both printing `true`; `uncaught.json` is the one that fails — `Uncaught TypeError: not a function` on stderr, exit 1. The bridge's own tests are vitest, run from the repo root.
